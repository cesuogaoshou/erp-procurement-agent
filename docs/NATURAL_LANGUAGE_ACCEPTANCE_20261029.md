# 普通采购人员自然语言验收记录

验收日期：2026年10月29日。结论：**部分通过，尚未通过面向非技术用户的完整业务验收。**

本轮实际执行了19次纯自然语言请求，其中16次通过项目接口调用真实模型，3次在浏览器填写并运行；另外完成6项页面审批流程检查。没有让采购人员输入内部物料编号、程序参数或工具指令。

19次请求的建单结果、数量及本轮预算/权限约束检查符合预期，6项审批流程检查通过。但是3次代表性页面复核都有结果可读性问题。不能把“没有错误建单”解释为“用户已经看懂并完成业务”。本轮没有修改业务代码。

## 普通人怎么操作

1. 打开本机采购页面，使用采购员身份登录，进入“智能采购”。
2. 将下表中的整句话填入采购需求框，不需要知道任何内部编号。
3. 在“确认整单预算（元）”输入框填写对应金额。仅了解库存、不购买时可以留空。“没有确认预算栏”用例特意留空，“预算冲突”用例特意保留旧金额。
4. 点击页面现有的“运行真实Agent”按钮，等待执行结束。
5. 检查系统有没有买错物料、改变数量、超出预算、放宽交期；再检查是否用中文说明结果、没有成功的原因和下一步操作。
6. 需要下单时由采购员到“采购审批”点击“提交”，再由审批员登录审批。采购员自己不能批准。

每次运行都可能新增测试草稿。下面是本轮已经执行的记录，不需要重复执行才能查看结果。

## 需要整改的业务问题

1. **优先：必须给出中文结果和下一步。** 零数量应说“采购数量必须大于零”；预算不足应说“当前预算无法购买120件标准轴承，本次未生成订单”；未说物料应追问“您要买什么？”。不能统一提示执行完成。需要补充或确认信息的场景，应进入明确的待补充状态。
2. **优先：正常草稿显示物料名称、单位、数量和交期。** 用户不应通过数字“1”和右侧技术记录猜测采购的商品。内部状态要转换为“草稿已生成”“待审批”“已批准”“已驳回”等中文。
3. **优先：审批前提供能核对的订单详情。** 当前审批页主要展示供应商、金额、预算和状态，缺少物料明细、数量、单价、交期及推荐理由的查看入口。现有流程虽能批准，也不足以让非技术审批员可靠判断该不该批准。
4. **优先：补足确认流程。** 文字预算与预算栏冲突、缺少预算、起订量需要多买时，明确说明冲突或缺项，要求用户确认后再继续；本轮这些场景没有错误建单，但交互没有完成。
5. **随后：将技术执行记录收起为详情。** 主区域呈现中文业务结论，技术记录供排查使用；登录过期、版本冲突也应给出易懂提示。驳回窗口的确认、取消按钮应使用中文。

建议修复后原句复测，验收同时满足“订单正确”“不越过用户条件”“说明清楚、能继续操作”。本轮未修改功能，也未将既有整改验收的71项通过结果替代本轮用户体验结论。
